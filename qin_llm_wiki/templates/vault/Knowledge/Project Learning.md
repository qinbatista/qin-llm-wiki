# Project Learning

Read only the exact project's relevant Knowledge sections and up to five compact events. Use `ai_memory.py recall --project ProjectName`; missing vaults or unmatched projects are a normal skip. Never fill a gap with another project's memory.

Keep current code structure, interfaces, UI preferences, document organization, and durable decisions in one current owner. Session/task keys are provenance, not retrieval barriers. Source and current Knowledge outrank historical events.

The main task verifies changed behavior with the smallest useful check. Simple value edits may skip testing; avoid full builds or startup unless requested or necessary for the stated acceptance. Ending uses the user's selected model and effort only to summarize and save useful memory. It creates no verification or repair loop, and writes nothing when there is no durable change.

Use one outcome event and one stable issue ID for a repeated Bug. Preserve the actual verification status; `ACTIVE`, `MONITORING`, `RESOLVED`, and `ARCHIVED` describe the issue's current state. Use `amend` for missing details and render generated views after writes. Promote only evidence-backed general lessons; keep project-specific decisions with their project.
